# Painter's Eye MVP 验证协议

版本：1.2（2026-08-11：对照刺激改为明显高于阈值；判定规则 1 放宽；支持仅重测盲测；校准精简为 44 题）  
适用算法：`1.1.0-mvp-adaptive` 及同一规则的后续补丁版  
状态：自动化验证通过；固定显示器人体试验待执行

## 1. 目标与边界

本协议检验一个有限命题：在记录的显示条件下，个性化增强能否提高同一用户对未见颜色刺激的辨别表现，同时保留蓝黄和明暗控制信息。

本协议不检验医学诊断准确率，也不判断用户是否获得正常色觉者的主观体验。通过结果只能描述当前浏览器、显示器、环境和任务。

**本协议的适用范围不包括快速体验的通用预设。** 快速路径（8 题分流 + 预设增强）是降低使用门槛的近似模式：它不测量个人阈值、不经过盲测、不保存正式配置，界面中统一标注「近似模式」。第 2 节的判定规则只约束个性化精准测试产生的正式配置。

## 2. 预注册的判定规则

在查看人体结果前固定以下规则（v2，2026-08-11 修订；变更说明见文末）：

1. 个人增强正确率必须严格高于原始颜色正确率。通用增强作为参照在结果页报告，不参与判定：每种条件样本量很小，让通用条件的一票否决会把随机噪声变成裁决者。
2. 个人增强的控制轴正确率最多可比原始颜色低 5 个百分点。控制轴刺激以明显高于阈值的色差呈现（见第 4 节），因此该检查衡量的是转换造成的真实损伤，而非阈值噪声。
3. 反应时间只作辅助报告，不得用反应时间掩盖正确率未通过。
4. 盲测失败时不保存或自动启用正式个人配置；用户仍可查看原始数字图像。失败后允许保留校准结果，换一组未见刺激仅重测盲测（约 2 分钟）；只有用户主动选择时才完整重新校准。
5. 不得在看到结果后放宽阈值。需要改变规则时，先发布新协议版本，再收集新数据。

应用中的 `summarizeValidation` 实现前两条规则。

## 3. 校准协议

### 显示条件

使用一台固定显示器。测试者需记录显示器名称、分辨率、缩放、浏览器版本、亮度、系统色彩配置、环境光和观看距离。关闭自动亮度、Night Shift/夜览、True Tone/原彩、HDR、护眼模式和系统色彩滤镜。

### 刺激与回答

每题显示一个四方向 Landolt C 点阵。用户用方向键或屏幕按钮进行四选一强迫选择。系统记录完整刺激参数、答案、正误、反应时间和时间戳。用户看不清时也必须按第一感觉作答。

### 自适应阶梯

系统交错运行四条阶梯：protan、deutan、蓝黄控制和明暗控制。每条轴最多 10 个原创试次，另插入 4 个隐藏重复试次，共 44 题。

阶梯使用两次连续正确下降、一次错误上升规则：

- protan/deutan 起始色差 0.120，初始步长 0.018；
- 蓝黄控制起始色差 0.100，初始步长 0.015；
- 明暗控制起始色差 0.060，初始步长 0.010；
- 每次方向反转后，步长缩小到原来的 75%，下限为 0.001；
- 色差限制在 0.005–0.250。

拟合优先使用最后六个反转点。反转不足时，系统结合最后六题的色差和回答正误估计阈值，并扩大不确定范围。置信度同时考虑样本量、反转数和隐藏重复的一致性。

## 4. 独立盲测

校准结束后，系统使用不同种子生成 8 个未见基础刺激，每个刺激分别在三种条件下呈现，共 24 题：

- 原始数字颜色；
- 固定参数的通用红绿增强（severity 0.6、推荐强度 0.7、chromaGain 0.35、lightnessGain 0.01）；
- 当前用户的个人增强。

采用配对设计：同一基础刺激（相同种子、轴、色差、开口方向和点阵几何）在三种条件下各出现一次，仅颜色变换不同。条件间正确率差异因此只反映变换效果，而不是抽到不同题目的运气。

每个基础刺激的色差取该轴校准阈值的 1.25 倍（限制在 0.005–0.250），难度跟随用户本人的测量阈值，而不是固定常数。四条轴各出现两个基础刺激。例外：蓝黄与明暗两条控制轴的刺激以阈值的 4 倍呈现（下限 0.060）——控制题的目的不是测量阈值，而是暴露转换对已有辨色能力的损伤；按阈值边缘出题会让一次手滑被误判为副作用。

系统随机混合全部 24 题，不向用户或界面暴露当前条件。结果页报告三组正确率、中位反应时间、个人增强的控制轴正确率、各轴阈值和重复一致性。

## 5. 画作观察

盲测通过后才进行画作观察。先看原始数字图像，再开启推荐强度。每幅作品记录以下信息：

- 原图中能否辨认预定色彩区域；
- 增强后区域分离是否改善、无变化或变差；
- 中性色、肤色、明暗和整体自然度是否失真；
- 用户最终选择的强度；
- 按住原图对照时，缩放与位置是否保持。

五幅红绿目标作品中，至少三幅应报告区域分离改善，且推荐强度下不得出现一幅“无法接受”的明显失真。《神奈川冲浪里》作为蓝色主导控制作品，整体自然度需达到 4/5 或更高。任何软件错误、图像错位或原图不可恢复都会使试验失败。

画作判定只说明工具是否有用和自然，不把增强颜色解释为正常色觉者所见的真实颜色。

## 6. 短复核

同一配置默认最多每 30 天要求一次短复核；显示器指纹变化时立即复核。短复核包含 4 个主要混淆轴试次、2 个蓝黄控制试次和 2 个明暗控制试次。

复核失败不会删除旧配置。应用根据主要轴和控制轴表现，提示检查显示设置或重新完整校准。在通过前，用户可以只看原图。

## 7. 自动化软件验证

人体试验前必须通过：

```bash
npm ci
npm run check
npm run test:e2e
git diff --check
```

自动化验证包括：

- sRGB、Machado 矩阵、OKLab 补偿和 LUT 不变量；
- 自适应答案会改变后续色差，回答正误会改变拟合阈值；
- 强度 0% 与原始画面像素一致；
- GPU 渲染与 CPU 降级路径；
- 配置迁移、校验和、导入失败保护和刷新恢复；
- 完整首次流程、键盘操作、显示变化短复核和离线重载；
- 六幅本地画作及 PWA 预缓存。

自动化测试不能替代色弱用户本人在固定显示器上的感知试验。

## 8. 数据完整性

- 保留导出的校验和配置和原始试次；不要手改文件。
- 记录算法版本、应用提交、测试日期和浏览器版本。
- 记录失败、暂停、猜测和显示设置变化。
- 不删除不利结果，不用后续调参覆盖同一次试验。
- 若失败，保留结果并把版本标记为实验性；修正后使用新版本重新校准。
